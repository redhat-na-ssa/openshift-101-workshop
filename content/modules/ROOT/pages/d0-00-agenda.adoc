= Day Zero Agenda: Container & OpenShift Fundamentals

Day Zero is a one-day introduction for infrastructure and VMware administrators who have never worked with containers, Kubernetes or OpenShift.
It is built for a virtual classroom: short talks, live demos, and Q&A at the end of every module.
No coding is required, and nobody is expected to memorize YAML.

Days One and Two of this workshop go deeper and assume what Day Zero teaches.

== Outcomes

By the end of Day Zero, participants can:

* Explain what a container is at the operating system level, and why it is not a small virtual machine.
* Describe the core Kubernetes objects (Pods, Deployments, Services, Namespaces) and how they keep an application running.
* Say what OpenShift adds to Kubernetes, and find their way around the OpenShift web console.
* Explain how applications get their settings, storage and network access.
* Work through the first troubleshooting steps for an application that won't start.

== How the demos work

The instructor runs every demo live.
If you have access to the workshop cluster, you can run the same steps in your own project as the instructor goes.
Steps marked *Instructor only* need administrator rights or a Linux machine, so just watch those.

Everything you need to follow along is in xref:setup-requirements.adoc[Setup Requirements].
The short version: a web browser, and either the `oc` command-line tool on your computer or the web terminal in the OpenShift console.

=== Log in from the command line

In the OpenShift web console, open the menu under your user name in the top right and choose *Copy login command*.
Log in again if you are asked, then select *Display Token*.
Copy the command shown under *Log in with this token* and run it in your terminal.
It looks like this:

[source,sh,role=execute]
----
oc login \
  --token=sha256~REPLACE_WITH_YOUR_TOKEN \
  --server=https://api.REPLACE_WITH_CLUSTER_DOMAIN:6443
----

Confirm who you are logged in as:

[source,sh,role=execute]
----
oc whoami
----

Confirm which project your commands will run in:

[source,sh,role=execute]
----
oc project
----

Every demo command runs in your current project, so check that it names your own project before you start.

=== The example files

The demos create objects from small YAML files.
Each page shows the file it uses, and the commands read the same files straight from the workshop's repository, so there is nothing to download.
