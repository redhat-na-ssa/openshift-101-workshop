= OpenShift 101 Workshop

This repo holds the OpenShift 101 Workshop site: three workshops that take attendees from containers and Kubernetes basics to building, running and troubleshooting applications on OpenShift.
Attendees and instructors use the site, https://redhat-na-ssa.github.io/openshift-101-workshop/[redhat-na-ssa.github.io/openshift-101-workshop]: its *Workshop Instructor Guide* page has what an instructor needs to run a delivery, and its *Workshop Attendee Guide* page is where attendees start.
This README is for the people who maintain the workshops.

The site look, the PDF look, the build and release workflows and the Helm chart come from https://github.com/redhat-na-ssa/workshop-common[workshop-common], which the other workshop repos share, so change those there.

== Layout

The site is one Antora component, so a single navigation spans every workshop.

[cols="1,2",options="header"]
|===
|Path |What it holds

|`content/`
|The home part: the Workshop Home, Workshop Instructor Guide and Workshop Attendee Guide pages, and the `antora.yml` whose title, navigation and attributes the whole site uses.

|`workshops/containers-for-vmware-admins/`
|Containers and Kubernetes for VMware Admins.

|`workshops/openshift-fundamentals/`
|OpenShift Fundamentals.

|`workshops/running-applications/`
|Running Applications.

|`tools/install.sh`
|The command-line tools the workshops need beyond the shared ones, for the release's tools image (none so far).

|`deploy/`
|Helm values for running the site with a terminal and a web console in Showroom.
|===

Each workshop folder holds its own `antora.yml`, which applies only when the workshop is built alone, and its pages, navigation, images and examples under `modules/NAME/`.
An attribute a workshop needs must also be in `content/antora.yml`, because in the full site that file's attributes replace the workshop's.

== Previewing

With https://github.com/redhat-na-ssa/workshop-common[workshop-common] checked out next to this repo, run this from this repo's folder to preview the whole site:

[source,bash]
----
../workshop-common/scripts/preview.sh --watch
----

It builds the site the way the Pages workflow does, serves it on http://localhost:8080/ and rebuilds it when you save a change.
It needs Node.js and Python 3.

To build one workshop on its own, the way it is tested before it joins the site:

[source,bash]
----
../workshop-common/scripts/preview.sh \
  --watch \
  --workshop openshift-fundamentals
----

Every pull request runs *Check content*, which holds the lines it changes to the formatting conventions and checks that the site and each workshop on its own build without warnings or broken links, and *Test PDF Build*.
A merge to `main` publishes the site.

== Adding a Workshop

From this repo's folder:

[source,bash]
----
../workshop-common/scripts/add-workshop.py NAME "Title"
----

It creates `workshops/NAME` from the workshop template and lists it in both playbooks, in the home part's navigation and on the home, instructor and attendee pages.
Then write its pages, fill in its row on the instructor page and its setup requirements.

== Releases

Run the *Release* workflow from the Actions tab with the next version, such as `v1.1.0`, or push a tag of that name.
It publishes the PDF, the runtime and tools images, the Helm chart and an offline bundle; see "Releases" in workshop-common's README.
To ship another file with every release, put it in `downloads/`.
The tools image has only the shared tools; `tools/install.sh` adds none.
The one other command-line tool the pages use, `podman`, runs on an attendee's workstation or the instructor's Linux host, because the tools pod has no container engine.
